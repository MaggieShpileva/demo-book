# Figma → Code

Правила универсальны для React-проектов со стеком: CSS Modules + SCSS, Feature/UI-слои, path aliases. Адаптируй пути и имена токенов под конкретный репозиторий, не копируй Tailwind / absolute-layout из Figma MCP as-is.

## Анализ макета → компоненты

- Не копируй структуру узлов Figma буквально.
- Сначала проанализируй макет и выдели логические React-компоненты.
- Один Frame Figma не означает один React-компонент: группируй по смыслу и переиспользованию (карточка, хедер, список, модалка), а не по вложенности слоёв.

## Слои и структура

- Экран / фича → `components/Feature/<Name>/` (или принятый в проекте Feature-слой)
- Переиспользуемый примитив → `components/UI/<Name>/`
- Страница → тонкая обёртка в `pages/` без вёрстки
- В каждой папке: `Name.tsx` + `Name.module.scss` + `index.ts`
- Вложенные блоки — в `components/<Child>/` с той же тройкой файлов
- Named export, `FC`, типы пропсов рядом с компонентом

## Переиспользование UI

Перед созданием нового элемента:

1. Найди существующий UI-примитив (Button, Title, Typography, Modal, Input…)
2. Расширь через `className` / `variant` / props
3. Новый компонент — только если аналога нет

Не дублируй примитивы ради пиксель-перфекта.

## Стили (обязательно)

**Каждый** `*.module.scss` / SCSS-файл компонента начинается с:

```scss
@use "@styles/index.scss" as *;
```

Без этого импорта токены, миксины и типографика проекта недоступны. Не подключай отдельные `_colors` / `_mixins` напрямую, если есть единая точка входа `@styles`.

Далее:

- CSS Modules, классы в **camelCase** (`.imageContainer`), не классический BEM `--modifier`
- Цвета, отступы, шрифты — только из design-токенов проекта; сырой hex — если токена нет
- Масштабирование — **одна** глобальная CSS-переменная `--ui-scale` (задаётся в `styles/global-ui-scale.scss` через `dynit`). В компонентах не заводи локальные `--*-scale` и не дублируй `dynit`:

```scss
// styles/global-ui-scale.scss — единственное место с dynit
:root {
  --ui-scale: 1;
  @include dynit(--ui-scale, 1, 1.2375, 375, 768, $unit: "");
}

// в компоненте — только умножение на var(--ui-scale)
.container {
  padding: calc(16px * var(--ui-scale));
  width: calc(124px * var(--ui-scale));
}
```

- Не переноси rem/vw/Tailwind из экспорта Figma — px из макета × `var(--ui-scale)`
- Классы склеивай через `clsx`
- `rgba()` в legacy-нотации, если так требует stylelint проекта: `rgba(255, 255, 255, 0.3)`

## Ассеты

- Растр → `assets/images/<feature>/`, в формате webp, имена **kebab-case**
- Иконки → `assets/icons/*.svg`; для React — `?react` (SVGR)
- Импорты с префиксом формата: `WEBP_`, `PNG_`, `SVG_`

## Поведение и анимации

- Анимации — библиотека проекта (`framer-motion` / CSS), без лишнего шума
- Блокировка скролла в оверлеях — утилита проекта (`lockScroll` и аналоги)
- Глобальное состояние — store проекта (Redux Toolkit); локальный state — только для UI-мелочей

## Чеклист перед сдачей

1. Компоненты выделены логически, а не 1:1 с Frame/Group из Figma?
2. В **каждом** SCSS есть `@use '@styles/index.scss' as *;` первой строкой?
3. Есть ли уже UI-компонент / токен / похожий паттерн?
4. Структура Feature/UI + `module.scss` + `index` соблюдена?
5. Размеры через `var(--ui-scale)`, без локальных scale-переменных?
6. Нет Tailwind / inline-стилей из MCP?
7. Ассеты в папке фичи, импорты с префиксами?
